# プラハチャレンジのDDDモデル案

ステータス: レビュー後修正版

## 目的と範囲

プラハチャレンジに登場する概念と、それらに付随する情報・ルールをDDDのモデルとして整理する。

これは学習用アプリケーションのモデル案であり、本番運用に必要な仕様や、本文にない制約は追加しない。

用語の定義は [CONTEXT.md](../CONTEXT.md) を参照する。

メール送信の方法、ランダム選択の実現方法、データの保存方法などの技術的な詳細は、この文書では定義しない。

## 概念モデル

プラハチャレンジには、次の概念が存在する。

```text
参加者（Participant）
├── 在籍ステータス（EnrollmentStatus）
└── 課題（Task）
    └── 進捗ステータス（ProgressStatus）

チーム（Team）
└── 所属参加者
```

「プラハチャレンジ」は、これらの概念を扱うドメインの名称である。参加者・チーム・課題を所有する別のエンティティとしては扱わない。

## 参加者

参加者は、名前・メールアドレス・在籍ステータスを持ち、複数の課題を所有する。

### 参加者の情報

- 参加者ID
- 名前
- メールアドレス
- 在籍ステータス
- 所有する課題

メールアドレスは参加者を識別する値であり、参加者間で重複してはならない。

在籍ステータスは次のいずれかである。

- 在籍中
- 休会中
- 退会済

在籍ステータスが「在籍中」ではない参加者は、どのチームにも所属してはならない。

## 課題

課題は参加者が所有する学習項目である。全ての参加者に複数の課題が割り当てられ、課題ごとに参加者固有の進捗ステータスを持つ。

このモデルでは、課題のタイトルや説明などの共通情報は扱わず、参加者が所有する課題とその進捗だけを扱う。

### 課題の情報

- 課題ID
- 進捗ステータス
- 所有者

進捗ステータスを変更できるのは、その課題の所有者だけである。

## チーム

チームは、名前と所属参加者を持つグループである。

### チームの情報

- チームID
- チーム名
- 所属参加者IDの集合

チーム名は英文字のみで構成され、チーム間で重複してはならない。

通常のチーム人数は2〜4名である。参加者の減少によって合流先がない場合は、1名のチームが残ることがある。この状態は通常状態ではなく、管理者への連絡が必要な例外状態である。

参加者は複数のチームに所属してはならない。

## 進捗ステータス

進捗ステータスは次のいずれかである。

- 未着手
- 取組中
- レビュー待ち
- 完了

遷移は次のとおりである。

```text
未着手 -> 取組中 -> レビュー待ち -> 完了
                         |
                         +-> 取組中
```

「完了」からは変更できない。

## 値オブジェクト

次の値は、値としての同一性や許可される値を表す。

- `ParticipantId`
- `TeamId`
- `TaskId`
- `EmailAddress`
- `TeamName`
- `EnrollmentStatus`
- `ProgressStatus`

`TeamName` は英文字のみを許可する。チーム名の重複禁止は、個々の `TeamName` ではなく、チーム全体のルールである。

メールアドレスの重複禁止も、個々の `EmailAddress` ではなく、参加者全体のルールである。

## 参加者が減る場合

参加者が休会または退会する場合、次の振る舞いを行う。

1. 参加者の在籍ステータスを変更する。
2. 参加者を所属チームから外す。
3. チームが2名以下になった場合、管理者へメールで連絡する。メール文面には、減った参加者、該当チーム、現在の参加者名を含める。
4. チームが1名になった場合、残った参加者を別のチームへ合流させる。
5. 合流先は、参加人数が最も少なく、加入後も4名以下となるチームから選ぶ。
6. 同人数のチームが複数ある場合は、ランダムに選ぶ。
7. 合流可能なチームがない場合は、その事実を管理者へメールで連絡する。メール文面には、減った参加者と合流先を探している参加者名を含める。

## 参加者が増える場合

休会中の参加者が復帰する場合、次の振る舞いを行う。

1. 参加者の在籍ステータスを「在籍中」に変更する。
2. 参加人数が最も少ないチームへ加入させる。
3. 同人数のチームが複数ある場合は、ランダムに選ぶ。
4. 加入によって5名になった場合、チームを2名と3名の2チームに分ける。分け方はランダムでよい。

## 課題の進捗を変更する場合

課題の所有者が、自分の課題の進捗を変更する。

- 「未着手」からは「取組中」にのみ変更できる。
- 「取組中」からは「レビュー待ち」にのみ変更できる。
- 「レビュー待ち」からは「取組中」または「完了」に変更できる。
- 「完了」からは変更できない。
- 所有者以外は進捗を変更できない。

## 整合性ルール

- メールアドレスは参加者間で重複しない。
- チーム名はチーム間で重複しない。
- 在籍中でない参加者はチームに所属しない。
- 参加者は複数チームに所属しない。
- 通常のチーム人数は2〜4名である。
- 5名になったチームは2名と3名に分かれる。
- 課題の進捗は所有者だけが許可された遷移で変更できる。

これらのルールを実装上どのクラスや関数が調整するかは、ドメイン概念とは別のアプリケーション設計で決める。
